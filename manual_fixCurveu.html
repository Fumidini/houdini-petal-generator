Fix Curveu - Re-assigning curveu
Resample で変わった curveu を、付け根 0 → 先端 0.5 → 付け根 1 にそろえ直し、先端の点を記録する。全 6 ステップ。
Resample changes curveu, so this rebuilds it as root 0 → tip 0.5 → root 1 and saves the tip point, in 6 steps.

Where is the tip?

日本語
getbbox_max(0) は、ジオメトリ全体を囲む箱（バウンディングボックス）のいちばん大きい角。その .z が花びらのいちばん先の高さ。
x と y は 0 にして、中心線の上・いちばん先の場所を「先端の目印」tip_P にする。

English
getbbox_max(0) is the max corner of the bounding box around the whole geometry. Its .z is the height of the very tip of the petal.
x and y are set to 0, so the marker tip_P sits on the centerline, at the very top.
This runs in Detail mode, so it is computed only once for the whole geometry.

日本語
primpoints(0, 0) は、0 番のプリミティブ（輪郭のポリゴン）を作っている点の番号を、輪郭につながっている順に配列で返す。
n は輪郭の点の数。
点番号（@ptnum）の順ではなく、「輪郭をたどる順番」で扱えるのがポイント。pts[0] が付け根のスタート地点。
English
primpoints(0, 0) returns the point numbers of primitive 0 (the outline polygon), in the order they are connected along the outline.
n is the number of outline points.
The key is that we work in "order along the outline", not in @ptnum order. pts[0] is the starting point at the root.
3
先端にいちばん近い点を探す
Find the point closest to the tip
// Find the closest point to the tip
int tip_index = -1;
float min_dist = 1e10;
for (int i = 0; i < n; i++)
{
vector P = point(0, "P", pts[i]);
float dist = distance2(P, tip_P);
if (dist < min_dist)
{
min_dist = dist;
tip_index = i;
}
}
全文で見る ↓ See in full code
日本語
「いちばん小さい値さがし」の定番の形。
① min_dist をとても大きな値（1e10）で始める
② 並び順に全部の点を見て、tip_P との距離を測る
③ 今までの記録より近ければ、その距離と順番 i を更新 → 最後に残った i が tip_index
distance2() は距離の 2 乗。平方根を計算しないぶん軽く、大小をくらべるだけならこれで十分。
メモ：tip_index は点番号ではなく、配列 pts の何番目か（輪郭上の並び順の位置）。点番号は pts[tip_index]。
English
The classic "find the smallest value" pattern.
① Start min_dist at a huge value (1e10)
② Visit every point in outline order and measure its distance to tip_P
③ If it is closer than the record so far, store that distance and the index i → the i left at the end is tip_index
distance2() is the squared distance. It skips the square root, so it is cheaper, and it is all we need to compare sizes.
Note: tip_index is not a point number: it is the position in the pts array (the order along the outline). The point number is pts[tip_index].

5
u を振り直す
Re-assign u
// Redistribute u points in order
for (int i = 0; i < n; i++)
{
int pt = pts[i];
float u;
if (i <= tip_index)
{
// Root → Tip
u = fit(float(i), 0.0, float(tip_index), 0.0, 0.5);
}
else
{
// Tip → Root
u = fit(float(i), float(tip_index), float(n - 1), 0.5, 1.0);
}
setpointattrib(0, "curveu", pt, u, "set");
}
全文で見る ↓ See in full code
日本語
先端（tip_index）を境に、並び順 i を 2 区間に分けて u を割り当てる。
前半（付け根 → 先端）：0 〜 tip_index を 0 〜 0.5 に
後半（先端 → 付け根）：tip_index 〜 n−1 を 0.5 〜 1 に
最後に、点番号 pt = pts[i] に setpointattrib で書き込む。Detail からは @curveu で直接書けないので、この関数を使う。
メモ：先端の点はぴったり 0.5 になる。左右で点の数が少し違っても、どちらの辺も 0.5 で折り返すので、base と同じ「付け根 0 → 先端 0.5 → 付け根 1」の並びに戻る。
English
Split the outline order i into two ranges at the tip (tip_index) and assign u.
First half (root → tip): 0 … tip_index becomes 0 … 0.5
Second half (tip → root): tip_index … n−1 becomes 0.5 … 1
Finally write it to point pt = pts[i] with setpointattrib. In Detail mode you cannot write @curveu directly, so this function is used.
Note: The tip point gets exactly 0.5. Even if the two edges have slightly different point counts, both turn around at 0.5, so we get back the same "root 0 → tip 0.5 → root 1" layout as in Base.
6
先端の点を記録する
Save the tip point
// Save the tip point for later nodes (notch)
setdetailattrib(0, "tip_pt", pts[tip_index], "set");
全文で見る ↓ See in full code
日本語
後の notch で先端の点を使えるように、先端の点番号を Detail アトリビュート tip_pt（ジオメトリ全体でひとつの値）として保存する。
書き込むのは並び順の tip_index ではなく、点番号の pts[tip_index]。
後続のノードは detail(0, "tip_pt") で読めるので、先端をもう一度探しなおす必要がなくなる。
メモ：noise は点の数やつながりを変えないので、notch まで同じ点番号がそのまま使える。
English
So that notch can use the tip later, the tip’s point number is saved as the Detail attribute tip_pt (one value for the whole geometry).
What gets written is the point number pts[tip_index], not the order index tip_index.
Later nodes read it with detail(0, "tip_pt"), so nobody has to search for the tip again.
Note: noise does not change the point count or connectivity, so the same point number is still valid in notch.
